# ModpackTools 3.4.1 — Side-aware provider dependencies

ModpackTools 3.4.1 fixes dependency resolution for Modrinth relationships whose required project is intentionally available on only one environment side.

## Changes

- Provider-declared project dependencies now apply only on the client/server sides where the resolved dependency project is supported.
- A both-side mod can therefore depend on a client-only companion such as Mod Menu without ModpackTools inventing an impossible server requirement.
- Server-only provider dependencies are handled symmetrically.
- Missing provider targets remain required until the resolver finds a concrete project candidate, so the new side handling cannot silently hide an unresolved dependency.
- Loader-manifest dependencies remain strict and keep their existing side semantics; the hotfix is limited to provider-level project relationships.

## Compatibility

There are no command-line, project-schema, Packwiz-metadata, or machine-output contract changes in this hotfix.

Existing pins and downgrade policy are unchanged. The resolver still refuses genuine incompatible graphs and still requires explicit permission for downgrades.

## Validation

Pester regression coverage reproduces the provider-side failure with both client-only and server-only dependencies, verifies that unresolved provider targets remain blocking, and verifies that loader-manifest requirements are not weakened by the fix.

The normal CI workflow also validates the module manifest, complete test suite, release metadata, installable ZIP, repository installation, self-update rollback, and Nushell adapter before the automated release workflow may publish 3.4.1 from the tested `main` commit.
