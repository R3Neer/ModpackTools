# ModpackTools 4.0.1 — Reliable confirmations and shorthand help

ModpackTools 4.0.1 fixes interactive confirmations through the Nushell adapter
and makes the version 4 option vocabulary fully visible in command help.

## Changes

- Keep Nushell standard input attached to the terminal while the internal JSON
  request travels through a temporary file. `modpack self-update` and other
  interactive operations now wait for an answer instead of receiving an
  immediate end-of-input cancellation.
- Verify the public `-y` shorthand as an exact equivalent of `--yes` for
  `self-update`, including the no-prompt installation path.
- Show shared options and their supported short forms in detailed command help.
  Pages now expose `-h`/`--help`, applicable `-p`/`--project`, and operation-level
  `-n`/`--dry-run` and `-y`/`--yes` pairs.
- Support `MODPACKTOOLS_CONFIG_HOME` as an explicit configuration-directory
  override so integrations can run without changing the user's real settings or
  caches.

## Compatibility

There are no command, project-schema, Packwiz-metadata, or machine-output
contract changes. This release retains the intentionally breaking version 4
vocabulary; the updater command is `modpack self-update`, not the retired
`modpack --update` form.

## Validation

All 250 Pester 4.10.1 tests pass. Nushell 0.115.1 accepts the adapter, installer,
and contract through `nu-check`; the complete adapter contract exits successfully
with isolated configuration and preserves Unicode data, session project state,
structured output, colour routing, and terminal input. A real PTY confirmation
waits for input, and the public `modpack self-update -y` path installs without
prompting in its mocked update boundary.
