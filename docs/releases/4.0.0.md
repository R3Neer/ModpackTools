# ModpackTools 4.0.0 — Domain-oriented CLI

This release replaces the complete command vocabulary with a smaller,
domain-oriented CLI. Version 4 intentionally does not preserve 3.x syntax or
aliases.

```powershell
modpack project use vanilla-plus
modpack content list --match sodium
modpack content search sodium
modpack content add sodium -n
```

## Changes

- Group project operations under `project` and installed or available content
  under `content`. The inventory is now `content list`; there is no separate
  `inventory` command.
- Replace the inventory's ambiguous `--search` filter with `--match`. Searching
  Modrinth remains the explicit `content search` operation.
- Replace verb-like `classify` with the `category` domain and explicit `list`,
  `create`, `remove`, `assign`, and `clear` operations.
- Use `resource-pack enable|move|disable` and `mod set-side` for type-specific
  mutations. Adding and activating a resource pack uses `content add --enable-at`.
- Make `--project`/`-p` a true global option accepted before or after a command.
  Standardize `-h`/`--help`, `-V`/`--version`, `-n`/`--dry-run`, and
  `-y`/`--yes`; use the American-spelling `--color` presentation option.
- Keep `--version` strictly local and network-free. Release checks and installs
  now live under `self-update`, with `self-update --check` for a read-only check.
- Remove the old top-level commands and retired options rather than silently
  translating them. Scripts written for 3.x must be updated before installing
  version 4.
- Regenerate command help, project README guidance, architecture notes, and
  integration coverage around the new vocabulary.

## Validation

All 245 Pester 4.10.1 tests pass, including explicit rejection of the removed
3.x commands, global-option placement, shorthand normalization, help rendering,
transactions, dependency resolution, installation, and self-update boundaries.
Isolated installation and self-update integrations exercise the installed module
in fresh PowerShell processes. The live integration continues to cover real
Packwiz and Modrinth content when run with its external prerequisites.

Dependency checks validate declared metadata; they do not launch Minecraft or
prove runtime mod compatibility. Review `modpack --help` before migrating scripts.
