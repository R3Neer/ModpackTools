# ModpackTools 3.3.1

ModpackTools 3.3.1 tightens the Nushell command-line surface so Nu uses Nu-style option spelling instead of inheriting PowerShell-style parameter forms through the bridge.

## Changes

- Nushell long options must use lowercase double-dash spelling such as `--project`, `--no-human`, and `--allow-downgrade`.
- Nushell short options must use documented one-letter lowercase spelling such as `-h`.
- The Nu adapter now rejects PowerShell-style single-dash words such as `-Project` and `-project`, uppercase short options such as `-P`, and uppercase long options such as `--Project` before invoking the PowerShell bridge.
- The PowerShell CLI is unchanged; the restriction applies only at the Nushell adapter boundary.
- Existing Nushell machine mode, R3CLI presentation, UTF-8 transport, session-local `MODPACKTOOLS_PROJECT` state, and canonical PowerShell domain/parser implementation remain unchanged.

## Validation

The Nushell contract now verifies that invalid PowerShell-style and uppercase option spellings fail inside the Nu adapter without reaching the bridge, while normal lowercase double-dash options continue to work. The existing PowerShell regression, installation, self-update, machine-output, Unicode transport, colour, and session-state coverage remains in CI.
