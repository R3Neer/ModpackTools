# ModpackTools 3.2.0

Update ModpackTools itself with `modpack --update`, and see an update notification
when running `modpack --version`.

## Changes

- `modpack --update` checks the latest stable official release, shows the target
  installation and version change, and installs after confirmation. `--yes`
  supports unattended updates; `--check` only checks availability.
- `modpack --version` keeps the version line and announces newer stable releases.
  Successful checks are cached for 24 hours, with a short network timeout and
  graceful failure when offline. `--version --offline` skips network and cache.
- Downloaded updates require a matching SHA256 digest, official asset URL and
  matching package version/identity. Unsafe or ambiguous ZIP contents are rejected.
- Installation runs separately from the loaded module and follows user
  `PSModulePath` order. Other visible copies and shadowing installations are
  diagnosed. Open a new terminal after updating.
- The shared installer supports explicit user targets, serializes installations,
  preserves custom themes, validates the replacement in a fresh process and
  restores the old installation if that validation fails.
- Help, errors and status output follow the existing R3CLI catalogue and renderer.
  README and integration documentation describe the new commands and boundaries.

## Validation

All 220 Pester 4.10.1 tests pass, covering update checks, cache expiry, offline behavior, invalid packages,
confirmation, version comparison and installation selection, alongside the
existing regression suite. Isolated installation checks cover themes, hashes and
command help; the self-update integration uses the real installer and verifies
rollback after a post-replacement failure. Both integrations also run in CI.

`modpack update` continues to update pack content. Self-update does not modify or
repair modpacks. Existing versions need the release installer once to acquire the
new command.
