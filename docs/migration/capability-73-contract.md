# Capability 73: complete staged add/update/repair composition

Design before implementation. Close one complete content operation through the
accepted transaction, owned acquisition/resolver, materialization and real Packwiz
refresh boundaries. Retain full source preconditions, dry-run and failure recovery.
Include requested --category and --enable-at behavior; no partial public command
should silently omit these options. Numeric inventory/search/version references
keep their original contexts, selection priorities and expiry behavior.

The checked Before observation and acquisition ledger should be owned once, reused
by planning. Provider-specific Packwiz update remains an explicit native process
for non-Modrinth managed targets; --to is invalid there. Reobserve only when that
provider update actually changed the planning stage, retaining the original graph
baseline for policy. No repeated checked health traversal merely to pass dynamic
state between translated functions.

Requested classification/type errors precede materialization. Resource activation
requires Default Options and applies the requested block position after removing
selected entries; preserve selected order, remaining order and reversed storage.
Materialize declarations, apply requested editorial/resource settings, reread actual
selected versions, enforce graph policy, then invoke Packwiz under original trigger
conditions. Repair refreshes even without version changes. Stage IO/process errors
leave protected originals intact; dry-run computes complete actual file changes
without publishing them. Return owned results with paths rebased from temporary
stage to the original context.

Public CLI wiring must preserve option parsing and structured transaction envelope,
without exposing tool stdout or requiring PowerShell. Human presentation remains a
separate overall closure requirement. No install/live config/release/push is implied.
The original public grammar exposes content add/update; repair is the internal
operation used by doctor --fix, not a new content repair command. Preserve that.

MODPACKTOOLS_STATE_HOME is an advanced host bootstrap setting for a STABLE native
recovery namespace, defaulting to LocalAppData/ModpackTools/native-state. It is
independent of MODPACKTOOLS_CONFIG_HOME and has no per-command flag. Changing it
requires migrating pending state first. Isolated CLI tests set this once to their
owned fixture namespace; they must never create test journals in live user data.

Finite differential cases should cover complete add/dependency plus optional
classification/activation, same-version explicit add, update, repair, dry-run and
refresh failure. Use synthetic independent packs, loopback provider metadata and
the already verified real Packwiz executable. Declare data-preserving document
format refinements rather than claiming byte parity with the legacy corruptions.

Implementation 73 owns one ResolutionAcquisition and checked Before observation,
including candidate/artifact budgets. Public numeric references are resolved in
legacy priority order before stage preparation. A non-Modrinth update reobserves
only after its native provider tool runs. Category resolution and wrong-kind
checks precede document writes. Metadata paths in returned plans refer to the
protected project, not a disposable stage.

ProjectHealthObservation retains RawReport from its existing graph construction,
without another traversal. Planning uses the reconciled Report; add/update policy
uses raw before/after errors, and repair keeps its plan-report rule. A known-empty
provider must not disguise a newly introduced missing dependency at commit time.

TransactionPreview prepares bounded public output before pending publication.
Public add/update return the legacy data.transaction shape and file-change reasons
remain null. Optional cleanup diagnostics are an explicit error-reporting extension:
at most fifteen entries plus a summary, bounded messages/codes, complete paths,
and a 4MiB reserve within the 64MiB output budget. Post-committed cancellation or
cleanup never changes Applied=true into an unapplied error.

Native contracts and the explicit Native --verify-content-operations mode passed,

complete preview/apply expectation, already-explicit no-op, wrong-kind rejection,
pre-publication output failure and native refresh failure with intact originals.
CLI protocol15, version and fresh-process Nu checks also passed.
