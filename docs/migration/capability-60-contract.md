Operation: ProjectHealth.ReadAsync(project,configuration,now,mode,limits,cancellation)
produces owned inventory, install observations, graph nodes, validator4 report and
provider availability evidence. No solver or transaction implementation, no health3
cache reuse and no claim of public human doctor support before its host is wired.
Build on accepted54–59 rather than recoding requirement evaluation or archive logic.

Read each managed metadata file once and parse a bounded syntax tree once. Preserve
the existing lexical public inventory projection; extract semantic download,
optional/default and pin facts from that same tree into owned values. Store facts
per occurrence/file, not in an ID dictionary that silently drops duplicates.
Preserve JavaVersion field presence separately from its value in ProjectContext,
without changing existing public project DTOs or rereading the descriptor.

Composition preserves original item ordering and duplicate identity rejection.
Installed provider versions use checked batch acquisition or offline56 observations.
Select primary file then first file, except same installed version with an exact
filename match takes precedence. A selected provider file blocks fallback to the
Packwiz download fields even when its digest is missing. Choose sha512 then sha1.
Resolve dependency version-only identities through provider metadata; required and
incompatible provider requirements retain SuggestedVersionId. Other dependency
types are omitted as in the original. Preserve explicit/transitive intent and
semantic pins/default optional selection.

Local mod JARs need no provider digest; read them using owned read-only handles and
bounded archive traversal. Managed artifacts use59. Unavailable/unreadable/limited
metadata creates truthful uncertainty, not invented declarations or healthy state.
Provider acquisition/metadata diagnostics may become node warnings as in the
original, but invocation cancellation/resource exhaustion propagate and cannot
be swallowed as a normal successful partial verification.

Graph environment includes declared Java, loader and Minecraft. Runtime override
presence retains explicit uncertainty. Reconcile only absent provider project
requirements with candidate availability: known-empty becomes unknown with code
provider.no-compatible-candidate; unknown availability preserves the existing
error. Retain issue key/schema2 and validator4; do not recompute identities with
legacy JSON issue keys. Report message/resource bounds still apply after refinement.

Each reusable client is invocation owned with explicit metadata/artifact budgets;
all models remain independent of renderer/global shell state. No cache-by-ID loses
occurrence diagnostics. Coordinate the supplied inventory/metadata snapshots rather
than running competing readers/writers or invoking the old PowerShell engine.

Acceptance targets complete isolated project health: local/managed artifacts,
version/file precedence, required/incompatible/linked identities, optional default,
pin/intent, Java, duplicate IDs, override files and known-empty versus unknown
provider availability. Original finite characterization and two incremental Native
reviews precede the green checkpoint. Public command activation, health4 persisted
cache and user presentation have separate complete acceptance requirements.
