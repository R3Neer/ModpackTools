with the same strict UTF-8 encoder used for writing. Prospective document/directory

One stage-only operation accepts the observed project context, a caller-owned stage
context and the immutable ContentPlan. It rebases installed metadata paths from the
observation root to the stage, computes every prospective output, validates all
destinations and document shapes, then writes and rereads the affected declarations.
Its receipt contains relative metadata paths and verified selected version IDs.
No provider requests, resolver rerun, cached JAR installation, Packwiz refresh or
protected-root commit belongs to this operation. Public add/update/repair still
requires their subsequent composition and acceptance.

Preserve original Set-MpPlannedContent behavior: existing custom metadata paths;
kind-derived new paths; selected filename and side fallback; sha512 preference;
download and Modrinth update fields; unrelated TOML keys, pin and option settings;
unknown editorial data; missing Content intents; requested add intents becoming
explicit even with no version changes. File-less changes skip Packwiz declarations.
Editorial persistence uses the original changes/requested-add conditions.

Validate the full batch before its first write, including new-file collisions,
duplicate destinations, root containment and selected filename containment. This
strengthens the original helper's per-file validation; the surrounding transaction
still owns rollback if an actual stage write fails.

Use bounded source-span TOML editing through the pinned Tomlyn syntax API. Preserve
unrelated text/comments; never replace apparent keys inside multiline string data
or interpret dollar signs as replacement tokens. Reject unsupported structural
ambiguities explicitly before writes instead of producing corrupt TOML. These are
intentional safe editing refinements over the legacy lexical patcher.

PSD output remains data literals, never executable PowerShell. Canonical formatting
may change comments/spacing as the original writer already did; parsed unknown
tables, arrays and scalar values must survive. Bound generated output and reparse
it before publication, comparing the complete typed data tree. The original writer
stringifies some nested arrays; retaining them is an explicit data-preservation
correction. A shape not representable by the supported data subset is rejected
before any stage write. Cancellation before writes leaves stage untouched; cancellation
or IO failure between stage writes relies on the enclosing stage transaction.

Finite tests: custom-path update; new declarations with dependency intent; requested
same-version add; unrelated TOML/PSD and options/pin preservation; literal dollars,
quotes/newlines; sha512 preference; whole-batch collision/containment rejection;
readback identity/version/hash; bounded output and cancellation. Reviewers compare
only this operation, without attributing later index or public-command behavior.
